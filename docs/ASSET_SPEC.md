# UI 画像アセットのコード化 仕様書(手番バナー/「かくてい」ボタン)

- 目的: 提供された PNG アセット(手番バナー・「かくてい」ボタン)を、画像ファイルに頼らず **コード(SVG + CSS、または Canvas)で描画**できるようにする。
- 対象アプリ: `game/`(TypeScript + Vite、DOM UI)。本書の数値は、リポジトリにある実画像(`game/src/assets/banner/turn-*.png`)をピクセル計測した値と、提供画像の目視による値。**目視値は「目安」**とし、最終的には参照画像との重ね合わせ比較(§9)で合わせること。
- 注意: 「かくてい」ボタン、青/緑の「あなたのターン」、青/緑の空白バナーは、こちらの環境にファイルとして届いていない(画像として見えているのみ)。そのため、それらは「橙版と同一構造で色だけ違う」前提で書いている。色の値は §2 の推定値。

## 3. 手番バナーの構造(709×355、上から重ねる順)

バナーは **3 本の太い筆跡(スワッシュ)を 3 層で重ねた形** + 文字。実測の外接矩形は x:52〜657, y:46〜313(余白あり)。
各層は「同じ筆跡パス」を太さ違いでなぞった線として作ると再現しやすい(`stroke-linecap: round; stroke-linejoin: round`)。

| 順 | 層 | 色 | 太さの目安 | 位置 |
|---|---|---|---|---|
| 0 | ドロップシャドウ | `--bn-shadow` | 全体を blur 8〜12px | 全層を合成した形を右下へ約 (6, 14)px |
| 1 | 外側の色帯(橙/青/緑) | プレイヤー色 | 最も太い(約 62px) | 基準パス |
| 2 | 黒帯 | `--bn-black` | 約 48px | 基準パスを左下へ約 (-4, +10)px ずらす |
| 3 | 白の縁取り | `--bn-white` | 約 36px | 基準パスを右上へ約 (+6, -10)px。上端が最も高い大きな丸い白帯(左上、約 x:150〜360, y:60〜170)を含む |
| 4 | 白帯の内側の黒 | `--bn-black` | 約 22px | 白縁の内側を通す |

筆跡パス(目安、座標は 709×355): 左下 (80,215) から左上へ弧を描き (250,110)、右へ (370,95)→(470,130) と波打ち、さらに 2 本目・3 本目の小さい波が右へ続き (590,140) で終わる「3 連の波」。
**最終形は参照画像と見比べて調整すること**(パスは目視近似で、厳密な座標は取れていない)。

### 3.1 文字(`banner-turn-*` / `banner-you-*` のみ)

- 位置: キャンバス中央やや上(`banner-turn`: 約 x 中心 355, y 中心 175 / `banner-you`: 同)。
- 書体: 丸ゴシック(`"M PLUS Rounded 1c"`, `"Hiragino Maru Gothic ProN"`, `"Yu Gothic UI"`, sans-serif の順にフォールバック)、weight 700〜800。
- サイズ: `banner-turn`「1Pのターン」は高さ約 56px(文字幅 約 390px)。`banner-you`「あなたのターン」は同サイズで幅約 510px。
- 3 重縁取り(外から): ①プレイヤー色の縁 約 10px → ②白の縁 約 6px → ③黒の縁 約 3px → 中身(塗り)は **白**。実画像では「黒い輪郭線の太字を、白→プレイヤー色の縁が囲む」見え方。
  - SVG なら同じ `<text>` を 4 枚重ねる: `stroke:色; stroke-width:20` → `stroke:#fff; stroke-width:12` → `stroke:#000; stroke-width:6` → `fill:#fff; stroke:none`(paint-order: stroke で 1 枚にまとめてもよい)。
- 「P」「1」などの英数字も同スタイル。文字内容は `{n}P のターン`(n=1..3)、`あなた のターン`。

## 4. 「かくてい」ボタン

キャンバス全体 709×約595、ボタン本体は約 x:52〜655, y:165〜425(横 約 600 × 縦 約 260、角丸 約 40px)。

層(外→内):
1. 黒の外枠: 太さ 約 14px、角丸。
2. 白の内枠: 太さ 約 12px。
3. 面: `--btn-gray`(#808080)。上端に薄い明るい帯(面の上 約 12px を `#9a9a9a` で)があり立体感を出している(目視)。
4. 文字「かくてい」: 横中央、高さ約 150px(幅 約 590px)、丸ゴシック太字。
   - 文字は **白い塗り + 黒の太い縁取り + さらに外側に白い細縁** の二重縁取り(参照画像では文字が白抜きの輪郭で囲まれて見える)。
   - SVG 例: `<text>` を 3 枚重ね(`stroke:#000;stroke-width:22` → `stroke:#fff;stroke-width:12` → `stroke:#000;stroke-width:5` + `fill:#fff`)。要・参照画像との重ね合わせ調整。

状態:
| 状態 | 見た目 |
|---|---|
| 通常(押せる) | 上記のとおり。黄 `#ffd54f` の脈動グロー(box-shadow を 0→8px、周期 1.1s)を外側に付ける。**transform(拡大)で脈動させない**(自動テストが「stable でない」と判定してクリック不能になった実績あり) |
| 無効 | 全体 opacity 0.45、グローなし |
| 押下 | translateY(2px)、影を縮める |
| 壁破り経路選択中 | 文字を「壁破りして移動」に差し替え(長いので文字サイズを 60% に縮小し 2 行可) |

## 5. 実装方針

推奨: **インライン SVG を返す TypeScript 関数**で生成し、DOM に挿入する(拡大縮小で劣化せず、`prefers-color-scheme` 非依存)。

```ts
// game/src/ui/art/bannerArt.ts
export type BannerTone = 'orange' | 'blue' | 'green';
export interface BannerOptions { tone: BannerTone; text?: string }   // text なし=空白バナー
export function bannerSvg(opts: BannerOptions): SVGSVGElement;       // viewBox="0 0 709 355"

// game/src/ui/art/confirmButtonArt.ts
export function confirmButtonSvg(label: string): SVGSVGElement;       // viewBox="0 0 709 595"
```

- バナー: `viewBox="0 0 709 355"`、`width:min(62%, 380px)` で表示。影は SVG `<filter>`(`feGaussianBlur`+`feOffset`+`feFlood` の合成)で実装。
- 文字は SVG `<text>`(外部フォントに依存しない)。フォントが無い環境でも崩れないよう `textLength` + `lengthAdjust="spacingAndGlyphs"` で幅を固定してよい。
- ボタンは `<button>` の中に SVG を `aria-hidden` で入れ、`aria-label` にテキストを持たせる(テスト ID `confirm-button` を維持、`disabled` 属性は `<button>` に付ける)。
- 既存の `TURN_BANNERS`(`game/src/ui/banners.ts`)と `.banner`(`controller.ts` の `banner()`)、`.btn.confirm`(`styles.css`)を置き換える。PNG は参照用として残してよい(比較テスト用、§9)。

## 6. 使用箇所とアニメーション

| 場所 | 内容 |
|---|---|
| 手番バナー | 手番開始時(配置フェーズ含む)に盤面上部中央へ表示。`banner-turn-{プレイヤー色}`。入力はブロックしない(`pointer-events:none`)。900ms: 0%: 縮小 0.6/透明 → 18%: 1.08 → 30%: 1.0 → 80%: 不透明維持 → 100%: 透明 |
| 「あなたのターン」 | 将来の CPU 対戦で人間の手番を示すために使う。現状のホットシートでは未使用(定義だけ用意) |
| 空白バナー | 文字を別に重ねたい場合の下地(例: 「壁を建てて」などのフェーズ案内)。現状未使用 |
| 確定ボタン | 盤面の下部中央に大きく固定。縦長画面では盤の下、横長で高さ 500px 以下では高さを縮小(min-height 44px) |

## 7. レスポンシブ

- バナー: 幅 `min(62%, 380px)`、縦横比 709:355 固定。
- ボタン: 幅 `min(60vw, 300px)`(横長の低い画面では `min(40vw, 220px)`)、縦横比は本体部分に合わせてトリミング(viewBox を y:150〜440 に切る)。セーフエリア `env(safe-area-inset-bottom)` を考慮。

---

## 8. アクセシビリティ

- バナー SVG に `role="img"` と `aria-label="プレイヤー1のターン"`(プレイヤー名を使用)。
- ボタンは `<button>`、フォーカスリング(黄の 3px アウトライン)を `:focus-visible` で表示。
- `prefers-reduced-motion: reduce` ではバナーの弾み・ボタンの脈動を停止し、フェードのみ。

## 9. 受け入れ基準・テスト

1. 見た目の一致: 参照 PNG(`turn-blank/p1/p2/p3/you.png`)と、同サイズでレンダリングした SVG を重ねて差分を取り、**輪郭がほぼ一致**(目安: 色差分の平均が閾値以下、位置のずれが 6px 以内)。Playwright の `toHaveScreenshot`(`maxDiffPixelRatio: 0.08`)で比較してよい。
2. 3 色(橙/青/緑)× {blank, turn, you} の 9 枚と、ボタン 1 種が同じ関数から出力されること。
3. 手番バナーが 900ms で消え、表示中にタップ入力が通ること(既存 E2E を維持)。
4. 確定ボタンが `data-testid="confirm-button"`、無効状態で `disabled`、脈動中も Playwright の `click()` が通ること(拡大アニメを使わない)。
5. 単体テスト(Vitest/jsdom 不要の純粋関数部分): 色・文字列の組み立て(`tone → 色`、`n → "nPのターン"`)。
6. `npm run build`、`npm test`、`npm run test:e2e`(3 プロジェクト)がすべて通ること。

## 10. 未確定事項(実装者が参照画像で決めること)

- 筆跡パスの正確な座標(本書は目視近似)。
- 青・緑版の厳密な色(橙と同じ明度・彩度で色相だけ変える前提の推定値)。
- 「かくてい」の文字縁取りの正確な層構成と太さ。
- 影の正確なぼかし量(実測では `rgb(74,74,74)` のアルファ 1〜2/255 が広範囲に続くので、ぼかし半径は大きめ=8〜12px)。
